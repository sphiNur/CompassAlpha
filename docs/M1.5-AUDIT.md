## 2 · Supplier-grouped purchasing data flow (#5 + #6)

**Schema:**
- `inventory.sku_supplier_links` (sku_id, supplier_id, isPreferred,
  defaultPrice, lastSeenAt) — many-to-many with `isPreferred` flag.
  This is the canonical "default supplier(s) for a SKU" table.
- `inventory.suppliers` (orgId, name, contact_phone, contact_tg,
  rating, …) — first-class entity, already shown in admin UI.
- `read_model.run_items_v.supplierId` — supplier captured at purchase
  time, currently the only place it lands.

**Event-sourced flow today:**
- Order events do NOT carry supplier (`ItemAdjusted.payload` =
  `{ skuId, qty, prevQty, byMemberId, forMemberId }`).
- Run plan-time event `RunPlanned.plannedItems` = `[{ skuId, qty }]` —
  no supplier.
- Run purchase-time event `ItemPurchased` carries `supplierId` (free
  pick at the till).

**Existing reusable bits:**
- `run.get` already returns `perStoreDemand: Array<{ storeId, skuId,
  qty }>` — the per-(store, sku) split the new views need.
- `catalog.suppliers` for the dropdown.
- `sku_supplier_links.isPreferred` as the "default supplier per SKU"
  source.

**Gap for the new feature:** `run.previewCreatable` only aggregates by
SKU. We need (a) `perStoreDemand` mirrored on the preview, (b) a
`supplierBySku: Record<skuId, { id, name }|null>` map joining
`sku_supplier_links` (preferring `isPreferred=true`, tiebreak by
`lastSeenAt DESC`).

**Action (Batch B):**
- Extend `run.previewCreatable` (server) with the two extra fields.
- RunPage (client) inserts a segmented control at line 863, branching
  to per-store / per-supplier views with a "Copy → send to vendor"
  affordance per supplier group.
- No event-schema changes. No migrations. Pure additive read-side.

## 4 · Back-nav coverage

**Critical bug found:** when a `<Sheet>` is open over an admin
`SectionFrame`, pressing the Telegram WebApp BackButton fires the
SectionFrame's drill-up handler instead of closing the sheet. 28
sheets are affected. Worst-case impact: 4 destructive purge sheets
(`AdminPage.tsx:4828, 4867, 5433, 5487`) — one accidental tap can
cascade because there's no escape via the platform "back".

**Fix (Batch A, single line in shared primitive):**
- Add `useTelegramBackButton(() => onOpenChange(false), open)` inside
  `packages/ui/src/components/Sheet.tsx`.
- React's useEffect cleanup-on-unmount handles stacking automatically:
  the topmost open sheet's handler registers last, wins, and on close
  the cleanup unwinds back to the parent's handler.
- Fixes all 28 sheets at once with no per-call-site changes.

Secondary cleanup items (will fold into Batch A or defer):
- 4 sheets missing `&& !mut.isPending` guard in `onOpenChange`
  (data-loss risk on slow networks):
  `MemberPermissionsSheet:2390`, `GrantRoleSheet:2816`,
  `ManageMemberSheet:1935`, `RunPage ConfirmActionSheet:2202`.

## 6 · Run page architecture (insertion point)

└─ <Card "Ready to plan">

exist on the preview — only on `run.get` (post-plan).

**Insertion point:** `RunPage.tsx:863`. Replace the flat `<ul>` with a
segmented control (`整体 / 按店铺 / 按供应商`) + a branched body. The
existing `<Card>` and header stay as-is so the visual frame doesn't
move.

**Server changes:** extend `previewCreatable` to return:
- `perStoreDemand: Array<{ storeId, storeName, skuId, qty }>`
- `supplierBySku: Record<skuId, { id, name, contactPhone, contactTg }
  | null>` (from `sku_supplier_links`, preferring `isPreferred=true`,
  tiebreak by `lastSeenAt DESC`)
