# Compass 重新设计方案

这份文档回答两件事：现在的界面哪里有问题，以及重做之后每一屏长什么样。视觉规范（颜色、字号、间距、组件）在根目录的 `DESIGN.md`，这里不重复。

状态：第 1 到 5 节是 2026-10-10 确认过的方案。**第 6 节是 2026-10-11 用户把页面布局和操作流程也交给我们之后的修订，与前文冲突时以第 6 节为准。**

## 1. 现状是怎么看的

现状截图由端到端主流程生成，带真实数据，走完"下单 → 审批 → 采购 → 送货 → 签收 → 完成 → 日结"：

```bash
E2E_SHOTS_DIR=/some/dir pnpm test:e2e
```

管理后台各分区另看了一组静态截图。那一组的文字全部渲染成同一个字号（开发服务器没有重新加载 Tailwind 配置），所以它显示的"顶栏文字重叠"和"导航标签被截断"在正确渲染下并不存在，不作为依据；页面结构和层级仍然可信。

## 2. 现状的问题

按对使用者的影响排序。

### 2.1 每一屏都在重复的东西

| 问题 | 证据 | 影响 |
|---|---|---|
| 顶栏占一整行，其中两样没有功能 | "Compass" 字样不可点；组织名是带虚线的文字，其实是设置入口 | 每屏损失 56px，设置入口没人找得到 |
| 底部 7 个标签，标签文字 9px | 全部角色共用一条导航；图标 + 9px 文字 | 字最小的地方恰好是最常点的地方 |
| 提示条盖住主按钮 | 采购、签收、日结三屏的成功提示都叠在吸底按钮上 | 刚操作完的两三秒里，下一步按钮被挡住 |
| 同类文字大小不一 | 分类/状态胶囊显示为 16px，而商品名是 13px | 次要的东西比主要的大。原因是样式合并工具把字号类当成颜色类丢掉了，是个一直存在的缺陷 |
| 小号全大写的分组标题 | "SUBMISSIONS IN T…"、"ITEMS"、"OFF-CATALOG & EXPENSES" | 被截断，而且在中文、俄文里全大写没有意义 |
| 卡片套卡片 | 门店切换弹层、设置弹层、审批卡片里的商品列表 | 层级靠边框堆出来 |

### 2.2 各屏自己的问题

- **下单**：数量为 0 的商品也显示完整的"− 0 +"，一屏 11 行里 9 行是空的减号。提交后，同一份订单被拆成状态卡、"你提交了什么"标题、预估总额卡、每个商品一张卡。
- **审批**：顶部最好的位置给了"待审 / 已通过 / 已拒绝"三个筛选，而审批人 99% 的时间只看待审。一张订单上并排 4 个动作（通过、拒绝、释放、收起）。头像圆圈里的姓名缩写不提供信息。
- **采购**：一屏里有 5 种不同样式的区块。价格显示成"12K"，分不清是单价还是合计。未购买的行右侧只有一个"✓"图标按钮，没有文字。"按分类"是一个孤零零的胶囊。结束采购的弹层里用 💵 🏦 表示付款方式。
- **签收**：每个商品下面一排横向滚动的选项（正常 / 少货 / 错货 / 质量…），最后一个永远被屏幕边缘切掉。全部正常是最常见的情况，却要先点"全部正常"再点"确认"。
- **历史**：只有一页也显示"上一页 / 下一页"；"筛选 (0)"常驻。
- **日结**：页面里又选了一次门店，而顶栏已经选过。金额输入框显示 `250000`，没有千分位。标题下面有一句解释这页是干什么的说明文字。
- **管理**：三层菜单卡片（管理 → 目录 → 分类）才到内容。分类列表每一项都常驻"编辑 / 归档"两个按钮，并显示 slug、排序号这类只有编辑时才需要的字段。"角色与权限"开头是一整段说明文字。价格报表、财务对账这些报表被放在"管理 › 运营"里，店长找不到。

## 3. 重新设计

### 3.1 一个原则压过其他：这是五个人的五个工具

下单的人、审批的人、采购员、收货的人、做日结的店长，各自一天只用其中一两屏。所以：

- **导航只放"要我做的事"**，最多 5 个，纯文字，后面跟待办数量：`下单 · 审批 3 · 采购 · 签收 1 · 日结`。没有权限的标签不出现，多数人只看到 2 到 3 个。
- **不是每天都做的事不进导航**：历史、报表、管理、设置收进导航最后一项"菜单"。它不能放在右上角：在 Telegram 里，屏幕顶部左右两角被 Telegram 自己的关闭和菜单按钮盖住。
- **打开应用落在有待办的那一屏**，没有待办时落在该角色的第一屏。

### 3.2 外壳

```
┌──────────────────────────────┐
│          中央厨房 ▾          │  顶栏：只有当前门店（可切换）。Telegram 里
├──────────────────────────────┤  居中，夹在它自己的两个按钮之间
│                              │
│  内容                        │
│                              │
├──────────────────────────────┤
│ 3 件 · 约 114,000 UZS        │  操作栏：一行摘要 + 一个主按钮
│ [        提交订单          ] │
├──────────────────────────────┤
│ 下单  审批 3  采购  签收  菜单│  导航：56px，纯文字
└──────────────────────────────┘
```

- 去掉 "Compass" 字样和组织名。组织名进菜单页顶部。
- 门店只在顶栏选一次。日结页和设置里重复的门店选择删除。
- 成功提示显示在操作栏**上方**，一次一条，不遮挡按钮。失败提示留在出错的位置，并带"重试"。
- 只有一个门店的人，顶栏左侧显示门店名但不可点。

### 3.3 下单

- 列表按分类分组，分类名是分组标题；顶部保留搜索，分类胶囊改成点了就滚动到该组。
- **数量为 0 的行只有一个"加"按钮**；加了之后才展开成"− 数量 +"。点数量可以直接输入。
- 行里商品名一行，下面一行次要信息：上次价格（有权限时）。
- 操作栏摘要：`2 件 · 约 114,000 UZS`，主按钮"核对订单"。
- 提交后是同一个列表的只读形态：顶部一行状态（`等待审批` / `采购中` / `已送达`），下面是下单的商品和数量，主按钮变成"再下一单"。不再拆成四种卡片。

### 3.4 审批

- 这一屏就是待审列表。每行：下单人 · 门店，下面是时间和件数，右边是预估金额。
- 点开一单 = 认领；返回 = 释放。"认领 / 释放"不再是按钮。
- 单内是商品列表，数量可改。操作栏：主按钮"通过"，旁边次按钮"拒绝"（拒绝在弹层里填原因）。
- "已通过 / 已拒绝"不再是顶部筛选，改为列表末尾的一行"查看已处理的订单"，进入菜单里的订单记录。

### 3.5 采购

三个阶段是同一屏的三种状态，标题直接说现在在哪一步。

**买货中**
- 列表分两组："还没买（1）"在上，"已买（1）"在下。
- 没买的行：商品名，下面是 `1 kg · 2 家店`，右边是文字按钮"记价"。
- 点一行打开弹层：单价（大号输入，带千分位）、数量、**付款方式（现金 / 转账，两个整行选项，默认沿用上一次的选择）**、主按钮"保存"、次按钮"没买到"。
- 已买的行：右边是**合计金额**，金额下方是付款方式标记；次要信息行写 `2 kg × 12,000`。不再出现"12K"。
- 列表末尾两个次按钮："加一个商品"、"加一笔其他支出"。其他支出记成普通的行，同样带金额和付款方式。
- "本次包含的订单"收成一行，点开看明细和"退回审批"。
- 操作栏摘要：`现金 24,000 · 转账 90,000`，右侧合计；全部处理完后主按钮"开始送货"可用，否则显示"还有 1 个没买"。

**送货中**
- 门店列表，每行一个状态标记（未送达 / 等待签收 / 已签收），点一行确认送达。
- 全部签收后主按钮"完成采购"，确认弹层里用文字和金额列出现金、转账、合计。

### 3.6 签收

- 列表：商品名 + 数量；有价格权限的人右边看到金额和付款方式标记，位置与采购屏相同。
- **默认路径一步完成**：主按钮"全部到齐"，点一下就确认。
- 有问题时点那一行，弹层里选问题（少货 / 错货 / 质量 / 没到，每个一整行），可填数量、备注、拍照。该行出现"少货"这样的状态标记，主按钮变成"确认，1 项有问题"。
- 横向滚动的选项条删除。

### 3.7 日结

- 门店来自顶栏。日期是标题的一部分："10 月 10 日 日结"，点它换日期。
- 表单是一列行：左边名称，右边金额输入，右对齐、等宽数字、输入时带千分位。分组：收入、支出与工资。
- 当天采购的现金、转账合计作为只读行自动带出（待核实接口是否已提供，没有就在这一屏的 PR 里补）。
- 操作栏摘要是算出来的结果，例如"应上交现金 476,000"，主按钮"保存日结"。
- 已保存过：顶部一行"已由 某某 保存 · 第 1 版"；再次保存时在弹层里填修改原因。常驻的说明框删除。

### 3.8 历史与报表（在菜单里）

- **采购记录**：按天分组，每天的小计带现金 / 转账拆分；行是门店 + 件数 + 金额。向下滚动加载，不分页。筛选只有一个按钮，点开弹层。
- **订单记录**：合并原来审批屏的"已通过 / 已拒绝"和管理里的"提交历史"。
- **价格报表**、**财务对账**：从"管理 › 运营"提到菜单的"报表"分组，按权限显示。

### 3.9 菜单与管理

菜单是一页分组列表，取代原来的设置弹层、管理首页、目录首页、运营首页四个中转页：

```
默认组织 · 你的角色
────────────
记录      采购记录 / 订单记录
报表      价格报表 / 财务对账
人员      门店与成员 / 角色与权限
目录      商品 / 分类 / 供应商 / 菜品 / 支出模板
我        显示名称 / 语言
系统      操作日志 / 维护（仅管理员）
```

- 列表页统一成：行 = 名称 + 一行摘要；点行进编辑弹层；"归档"在弹层里。slug、排序号、级别数字只在编辑时出现。
- 新建是每个列表页操作栏里的主按钮（"新建门店"）。
- "权限如何运作"那段说明删除；规则在出现限制的地方说，例如灰掉的角色旁写"高于你的级别"。

### 3.10 删掉和合并的屏

| 现在 | 之后 |
|---|---|
| 门店切换弹层 + 设置里的门店选择 + 日结里的门店下拉 | 顶栏一处 |
| 设置弹层、管理首页、目录首页、运营首页 | 菜单一页 |
| 审批的"已通过 / 已拒绝" + 管理的"提交历史" | 订单记录 |
| 导航里的历史、管理、调试 | 进菜单 |
| 下单提交后的四种卡片 | 同一列表的只读形态 |

## 4. 字号：还没定的一件事

规范里正文是 16px，而 2026 年 5 月因为现场反馈"字太大"刚把正文从 14px 缩到 13px。两件事需要放在一起看：

1. 现在线上的分类胶囊、状态胶囊实际就是 16px（2.1 里那个缺陷），用户每天在看。
2. Android 会按手机的"字体大小"设置把网页里所有文字再放大一遍，网页自己无法阻止。当时觉得大，很可能是这个原因，而不是 14px 本身大。

所以这次不靠猜：应用启动日志现在会上报每台设备的实际文字放大倍数（`app.boot` 的 `textScale`）。上线一两天后查一次就知道现场设备的分布，再决定正文是 16px 还是 15px。无论结论是哪个，新组件都按"文字放大到 1.3 倍也不截断、不重叠"来做：文字换行、行变高，不写死高度。

```sql
SELECT data->>'textScale' AS text_scale, platform, count(DISTINCT user_id) AS users
FROM ops.client_logs
WHERE data ? 'textScale' AND created_at > now() - interval '3 days'
GROUP BY 1, 2 ORDER BY 3 DESC;
```

## 5. 落地顺序

每步一个 PR，端到端主流程必须保持通过。

1. **外壳**：顶栏、导航、操作栏、提示位置、菜单页（先只放入口，内容仍是旧页面）。
2. **采购**（付款方式的源头）
3. **签收**
4. **日结**
5. **下单**
6. **审批**
7. **采购记录、订单记录、报表**
8. **管理各列表页**
9. 删除旧组件、旧字号表、旧主题。

采购、签收、日结连着做，是因为付款方式要在这三屏位置一致，一起做最不容易走样。

## 6. 流程修订（2026-10-11）

用户的原话："不仅仅是UI，页面布局，操作流程我都全权交给你们了，允许你们完全推倒重做。"

这一节重新过一遍整条流程：下单 → 审批 → 采购 → 送货 → 签收 → 日结。判断标准还是那一条：拿掉这一步，用户会少知道一件事或少做成一个动作吗？不会就删。

### 6.1 不动的东西

- **底层规则不动**：事件只追加不修改，按组织隔离，金额用十进制，日结用版本号防止互相覆盖。下面所有流程上的简化，都是界面把现有的几个命令连起来发，不新增事件，不改表。
- **六个环节本身不动**。每个环节对应一个真实的交接：店员把需求交给店长，店长交给采购员，采购员把货交给门店，门店把钱的结果交给账。少一个环节就少一次有人负责的确认。
- **权限不动**。谁能看到哪个环节，仍由现有权限决定。

要删的是环节**内部**多出来的点击和中转页。

### 6.2 入口：「今天」

现在的"菜单"页改名为**今天**，放在导航第一位，是应用打开后的第一屏。

- 顶部是计数块，每块是一件等着这个人做的事，点了就去做：待审批、待采购、待签收、今天还没日结。只显示本人有权限的。数字为 0 的块也显示，因为"没有待办"本身是他要知道的事。
- 下面是不常用的入口：采购记录、订单记录、报表、管理、设置。
- 只有一项工作的人（多数店员只下单，多数采购员只采购）打开应用直接进那一屏，不经过「今天」。

导航变成：`今天 · 下单 · 审批 · 采购 · 签收 · 日结`，没有权限的不出现。

### 6.3 逐环节：删掉什么

| 环节 | 现在要做的 | 改成 | 少了什么 |
|---|---|---|---|
| 下单 | 加数量 → 核对 → 提交 | 不变 | 核对弹层保留：它是提交前唯一一次看到全单的地方 |
| 审批 | 点"认领" → 改数量 → 点"通过" → 回到列表再点下一单 | 点开一单即认领，返回即释放；通过或拒绝后**直接打开下一张待审的单**，没有了才回列表 | 每单少两次点击 |
| 采购：开始 | 看预览 → 开始采购 | 不变 | |
| 采购：买货 | 逐项记价 | 不变（上次价格一键"已买"，其余点开弹层） | |
| 采购：转送货 | 点"开始送货" → 确认弹层 → 逐店点开 → 每店再确认一次 | 点"开始送货"**不再弹确认**：这一步在任何门店签收前都能撤回，撤回入口就在送货列表下面。送货列表里每家店一行，行尾一个"已送到"按钮，**点一下就记下，不再弹确认**；点错了点那一行可以收回，直到门店签收为止 | 一次采购通常送 3–4 家店：从 9 次点击降到 4–5 次 |
| 签收 | 点"全部正常" → 点"确认" | 主按钮就是"全部到齐"，一下完成。有问题的先点那一行标出来，主按钮变成"确认，1 项有问题" | 少一次点击 |
| 采购：结束 | 全部签收后点"完成采购" → 核对现金、转账 → 确认 | 不变 | 这是采购员对钱签字的地方，确认弹层保留 |
| 日结 | 选门店 → 填数 → 保存 | 门店来自顶栏；当天采购的现金、转账自动带出 | 少一次选择，少两个要抄的数 |

### 6.4 藏在 Telegram 菜单里的动作，放回屏幕上

"退回计划""撤回送货""取消本次采购"现在只在 Telegram 右上角的菜单里，浏览器里根本点不到，在 Telegram 里也没人知道它们在那儿。

改成采购屏最下面的一组行，只在能用的时候出现：

- 买货中："退回计划"、"取消本次采购"（红色，弹层里确认并填原因）。
- 送货中、还没有门店签收："回到买货"。

### 6.5 屏幕清单

| 屏 | 主操作 | 相比现在 |
|---|---|---|
| 今天 | 无（它是去别处的入口） | 取代"菜单"；合并了设置弹层、管理首页、目录首页、运营首页 |
| 下单 | 核对订单 → 提交 | 提交后是同一列表的只读形态，不再拆成四种卡片 |
| 审批 | 通过 | 列表只有待审；已处理的进"订单记录" |
| 采购 | 开始采购 / 开始送货 / 完成采购（随阶段变） | 预览、买货、送货是同一屏的三个阶段 |
| 签收 | 全部到齐 | 横向滚动的问题选项改成点行后的弹层 |
| 日结 | 保存日结 | 页面里不再选门店 |
| 采购记录 | 无 | 按天分组，向下滚动加载 |
| 订单记录 | 无 | 合并了审批的"已通过 / 已拒绝"和管理里的"提交历史" |
| 报表（价格、对账） | 无 | 从"管理 › 运营"提到「今天」 |
| 管理各列表 | 新建 | 统一成"行 + 编辑弹层" |

删掉的屏：设置弹层（并入「今天」）、管理首页、目录首页、运营首页、调试页的导航入口。

### 6.6 生产数据说了什么（2026-10-11，只读查询）

**多店是常态。** 148 次采购里，送 1 家店的 22 次，2 家 6 次，3 家 83 次，4 家 35 次。原先设想的"只有一家店时开始送货即送达"只对七分之一的采购有用，不做。省点击的地方改在每家店那一步上（见 6.3）。送货列表要按"每次三四行"来设计，不是一行。

**签收全部是"正常"。** 已签收的 13,518 行里没有一行标过少货、错货或质量问题。所以：

- 默认主按钮是"全部到齐"，一下完成，这一点可以放心。
- 但"从来没有问题"不太可能是真的。更可能是标问题太麻烦（现在是每行一排横向滚动的选项），于是大家都点了全部正常。新设计里标问题是"点那一行 → 弹层里选"，做完后值得再查一次这个数字，看它是不是从零变成了非零。

**照片功能实际上不存在。** 库里没有一张签收照片，也没有一张小票照片；对象存储的配置是占位符，上传本来就是坏的。重做的屏里**不放拍照入口**：一个点了必然失败的按钮比没有更糟。等接上真正能用的存储，再作为单独一项加回来。
