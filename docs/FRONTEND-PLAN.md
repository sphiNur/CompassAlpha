# Fine 前端方案

2026-10-11 用户批准。前端从零重做：不沿用此前的任何界面，也不照 iOS 做；设计语言取自 Wise。带画面的完整版是 `Compass/previews/fine-frontend-plan.html`（仓库外）。这里是文字版，供实现时对照。视觉规范在根目录 `DESIGN.md`。

确认的三项：产品名 **Fine**；主色 **亮绿配墨色字**；排版按 **俄文的长度** 留空间，四种语言都能切换。

## 三条原则

1. 打开就是待办，不是菜单。
2. 干活时全屏，只有一个按钮。
3. 每屏最重要的数字最大，放在墨色块里。

## 四个去处

没有权限的不出现。

| 去处 | 谁会看到 | 里面有什么 | 主操作 |
|---|---|---|---|
| 今天 | 所有人 | 等着我做的事，按紧急程度排：待审批的订单、待签收的货、进行中的采购。没有事时显示今天完成了什么 | 点一件事进去做 |
| 订单 | 店员、店长 | 本店今天和最近的订单，每张带状态 | 下单 |
| 采购 | 采购员、店长 | 进行中的那一次采购；下面是以前的采购，按天排，带金额 | 开始采购 / 继续采购 |
| 管理 | 管理员 | 商品、分类、摊位、门店、成员、角色、报表、个人设置 | 各列表里的"新建" |

不再是导航项的三样：

- **审批**：有待审的订单时出现在「今天」最上面；也能从「订单」里点开任何一张待审的单。
- **签收**：货送到了，「今天」上出现一张卡片，点进去签收。
- **日结**：默认没有。已经在用的组织保留，放在「管理」里。

## 两种屏

- **去处屏**（今天、订单、采购、管理）：底部有导航，用来看和选。
- **任务屏**（下单、审批、采购中、签收）：没有导航；顶部左边是"返回"；底部是一个主按钮和它上方的一行合计。

## 关键屏

1. **今天**：墨色块说有几件事；下面每件事一张卡片，自带按钮（审批、签收、继续采购）。
2. **下单**：搜索、分类分段；没报过的商品只有"加"，报了才出现数量；底部合计和"核对并提交"。
3. **审批**：打开即开始审，不用先认领；墨色块是预计金额；数量可以直接改；"拒绝"和"通过，看下一张"。
4. **采购中**：墨色块是还剩几项、进度条、已花多少（现金、转账）；有上次价格的一键"已买"，没有的"记价"；已买的行右边是金额，金额下面是付款方式。
5. **记一笔**：数量、单价、合计、现金或转账、保存、没买到。
6. **签收**：墨色块是送到的项数；平时主按钮是"全部到齐"；标了问题之后变成"确认，N 项有问题"。

## 砍掉和合并的

| 以前 | 现在 |
|---|---|
| 七个标签 | 四个去处 |
| 审批的认领 / 释放 | 打开即认领，离开即释放 |
| 开始送货前、每家店送达前的确认 | 去掉；每家店一个"已送到"，可撤回 |
| 签收：先全部标正常，再确认 | 一个按钮 |
| 日结 | 默认没有，按组织开启 |
| 拍照 | 去掉，存储接通后再加 |
| 设置弹层、管理首页、目录首页、运营首页 | 一个「管理」 |
| 藏在 Telegram 菜单里的撤回和取消 | 在采购屏底部 |

不变的：下单 → 审批 → 采购 → 送货 → 签收这五次交接；服务端、数据库和权限。

## 实现顺序

1. 设计语言：颜色、字、圆角、组件。产品名改为 Fine。
2. 骨架：四个去处的导航，任务屏的框架。
3. 今天。
4. 下单、订单。
5. 审批。
6. 采购。
7. 签收。
8. 管理。
9. 删除旧界面的全部代码。

保存、离线排队、多人同时修改这些界面背后的逻辑沿用已有的、测过的代码。
